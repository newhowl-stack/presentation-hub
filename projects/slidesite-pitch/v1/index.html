Big idea

SlideSite is the editing layer for AI-made HTML decks.

Creators keep using Claude, OpenAI, Cursor, GitHub, and Vercel. Teams get the missing workspace after the deck exists.

Generate

HTML deck is created by the user's preferred AI workflow.

Edit together

SlideSite adds thumbnails, reorder, WYSIWYG text, chat, and review.

Ship

Export PDF/PPT, present full-screen, and keep changes in GitHub.

Problem + opportunity

LLMs generate HTML presentations. Teams still edit by screenshot, Slack, and developer handoff.

The creation layer moved fast. The collaboration layer did not.

Creation

The output looks finished.

Claude or OpenAI can produce a polished scroll deck in minutes.

Editing

The workflow is brittle.

Non-technical reviewers cannot click text, move slides, or adjust a specific object.

Handoff

The team still needs deck mechanics.

They need version history, comments, exports, and presentation mode.

Solution landscape

Current tools ask teams to abandon the file they already made.

No-code presentation apps are polished, but they want the team to start inside their platform. Developer tools preserve HTML, but they expose the team to code. SlideSite sits between those worlds.

Solution

SlideSite turns HTML decks into lightweight collaborative projects.

It does not replace the tools that generate decks. It makes their output editable, reviewable, exportable, and safe to hand to a team.
